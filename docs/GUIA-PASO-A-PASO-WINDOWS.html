Guía paso a paso para ejecutar el proyecto

ICA Bienestar Animal · Angular 20 + Firebase (proyecto bienestar-animal-ica) · Windows con PowerShell

Esta guía recoge, en orden, todo lo necesario para poner a funcionar la aplicación en un computador con Windows, conectada al proyecto real de Firebase. Incluye los errores que aparecieron durante la instalación y cómo se resolvió cada uno, en el punto exacto donde suelen salir.

Cómo leer la guía. Los comandos se escriben en PowerShell, uno por línea, y se ejecutan con Enter. Las cajas rojas son errores que ya ocurrieron y su solución. Las verdes indican cómo saber que el paso salió bien.

1. Requisitos

ProgramaVersiónDónde se obtiene
Node.js22 o superior (LTS)https://nodejs.org — instalar con las opciones por defecto
Google ChromeRecientehttps://www.google.com/chrome
Cuenta de Gmail—Debe estar agregada al proyecto de Firebase (paso 3)

Después de instalar Node.js, cierre y vuelva a abrir PowerShell. Para comprobar: node -v debe mostrar v22… o superior.

Error: PowerShell no puede cargar «npm.ps1» porque la ejecución de scripts está deshabilitada.
Solución: usar npm.cmd y npx.cmd en lugar de npm y npx. Esta guía ya los escribe así. Otra opción, una sola vez: Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned.

2. Descargar el proyecto y ubicar la carpeta correcta

  1. En GitHub, en el repositorio Aplicacion-a-la-inteligencia-artificial-, pulse Code → Download ZIP.
  2. En Descargas, clic derecho sobre el ZIP → Extraer todo… → Extraer.
  3. Abra PowerShell y entre a la carpeta extraída:
cd C:\Users\SuUsuario\Downloads\Aplicacion-a-la-inteligencia-artificial--main
dir -Name
Error: «cd firebase» o «cd frontend» dice que la ruta no existe.
Causa: Windows crea una carpeta dentro de otra con el mismo nombre al descomprimir. Si dir -Name muestra solo Aplicacion-a-la-inteligencia-artificial--main, todavía está en la carpeta exterior. Entre una vez más: 
cd .\Aplicacion-a-la-inteligencia-artificial--main
dir -Name
Repita hasta que la lista muestre docs, firebase, frontend y firebase.json. Esa es la carpeta raíz del proyecto.
Correcto cuando dir -Name muestra las carpetas firebase y frontend.

3. Acceso al proyecto de Firebase

  1. Envíe su Gmail a quien creó el proyecto bienestar-animal-ica para que lo agregue en Configuración del proyecto → Usuarios y permisos con el rol Editor o Propietario.
  2. Abra https://console.firebase.google.com con ese Gmail y confirme que aparece el proyecto.
La consola nueva agrupa los productos por categorías en el menú izquierdo: Authentication está en Seguridad; Firestore Database en Bases de datos y almacenamiento; AI Logic en Servicios de IA; Hosting en Hosting y sin servidores. Si no encuentra algo, use Buscar productos, arriba del menú.

4. Publicar las reglas de seguridad

Desde la carpeta raíz del proyecto:

cd firebase
npm.cmd install
npx.cmd firebase login
npm.cmd run desplegar:reglas
  • npx.cmd firebase login abre el navegador: inicie sesión con el Gmail que tiene acceso al proyecto y acepte. Si pregunta por enviar información de uso a Google, puede responder n.
  • npm.cmd run desplegar:reglas publica quién puede leer y escribir cada colección de Firestore.
Correcto cuando al final aparece Deploy complete! y una línea Project Console: https://console.firebase.google.com/project/bienestar-animal-ica/overview.
Las advertencias de npm sobre paquetes obsoletos (deprecated) o vulnerabilities son normales y no impiden nada. No ejecute npm audit fix --force: cambia versiones y puede dañar el proyecto.

5. Descargar la cuenta de servicio

La carga de datos iniciales necesita un archivo de credenciales con acceso de administrador al proyecto.

  1. En la consola de Firebase, ícono de engranaje → Configuración del proyecto → pestaña Cuentas de servicio.
  2. Pulse Generar nueva clave privada → Generar clave. Se descarga un archivo .json.
  3. Cree la carpeta C:\claves, mueva allí el archivo y renómbrelo como ica.json.

Compruebe que quedó bien:

Test-Path C:\claves\ica.json
Debe responder True.
Error: ENOENT … no such file or directory, open 'C:\claves\ica.json' (o Test-Path responde False).
Causas encontradas:
  • El archivo quedó en otra carpeta, por ejemplo C:\Users\SuUsuario\Downloads\claves. Use la ruta real o muévalo a C:\claves.
  • Windows oculta las extensiones y el archivo quedó llamado ica.json.json. Para verlo: dir C:\claves -Name. Para corregirlo: 
    Rename-Item C:\claves\ica.json.json ica.json
Este archivo es secreto. Da acceso total al proyecto. No lo suba a GitHub, no lo envíe por chat ni por correo y no lo deje dentro de la carpeta del proyecto. Cuando termine la guía, bórrelo de la consola (paso 12).

6. Cargar los datos iniciales y crear el administrador

Sigue en la carpeta firebase. Escriba su correo y una contraseña propia (mínimo 10 caracteres con al menos un número):

$env:GOOGLE_APPLICATION_CREDENTIALS = "C:\claves\ica.json"
$env:SEMILLA_ADMIN_CORREO = "correo-del-administrador@gmail.com"
$env:SEMILLA_ADMIN_CLAVE  = "UnaClaveSegura2026"
npm.cmd run semilla

La carga crea los roles (Administrador, Evaluador, Consultor, Propietario), las especies, las libertades, los niveles y los 23 criterios de la norma, y el primer administrador. Puede repetirse sin duplicar datos.

Correcto cuando termina mostrando Administrador inicial: <su correo> (o El administrador … ya existe si se ejecuta otra vez).
Anote ese correo y esa contraseña. Son el usuario del administrador. Las tres líneas $env: solo duran mientras esa ventana de PowerShell esté abierta; si la cierra, debe escribirlas otra vez antes de repetir la carga.
Error: la carga usa un correo de ejemplo o no crea el administrador.
Causa: se ejecutó npm.cmd run semilla en otra ventana, o se cerró PowerShell, y las variables $env: se perdieron. Escriba de nuevo las tres líneas en la misma ventana y repita.

7. Iniciar la aplicación

Desde la carpeta firebase:

cd ..\frontend
npm.cmd install
npm.cmd start
  • La primera vez, Angular pregunta si desea compartir datos de uso (analytics). Responda lo que prefiera; no afecta.
  • La compilación tarda uno o dos minutos.
Correcto cuando aparece Application bundle generation complete y Local: http://localhost:4200/. Abra esa dirección en Chrome.
Deje esa ventana de PowerShell abierta mientras usa la aplicación. Si la cierra, la aplicación se detiene. Para detenerla a propósito: Ctrl + C.
Error: el puerto 4200 ya está en uso.
Hay otra ventana de PowerShell con la aplicación abierta. Ciérrela o deténgala con Ctrl + C y vuelva a ejecutar npm.cmd start.

8. Activar el ingreso con Google

Error: «Este método de ingreso no está habilitado en el proyecto de Firebase.» al pulsar Google.
No es un fallo de la aplicación: el proveedor está apagado en la consola. Se activa así:
  1. Consola de Firebase → menú izquierdo Seguridad → Authentication. Si es la primera vez, pulse Comenzar.
  2. Pestaña Método de acceso. Deje habilitado Correo electrónico/contraseña.
  3. Agregar proveedor nuevo → Google → active Habilitar.
  4. En Correo electrónico de asistencia del proyecto, elija su correo → Guardar.
  5. En la pestaña Configuración → Dominios autorizados, verifique que esté localhost.
  6. Vuelva a la aplicación, recargue con F5 y pulse Google. Si Chrome bloquea la ventana emergente, permítala desde el ícono de la barra de direcciones.

9. Ingresar como administrador y entender los perfiles

El usuario del administrador es el correo y la contraseña del paso 6. Se escriben en los campos Correo y Contraseña de la pantalla de ingreso (no con el botón Google, salvo que sea la misma cuenta de Gmail).

Como administrador se ve el menú Inicio · Predios · Usuarios · Roles · Cuenta.
Situación: «ingresé con Google y quedé como propietario».
Es lo esperado: la primera vez que una cuenta entra con Google, Facebook o Microsoft, la aplicación la registra como Propietario. Si esa cuenta debe ser administrador:
  1. Consola → Bases de datos y almacenamiento → Firestore Database → colección usuarios.
  2. Abra el documento cuyo campo correo es su Gmail; tiene rol: propietario.
  3. Cambie el valor de rol a administrador (minúsculas) y guarde.
  4. En la aplicación, cierre sesión y vuelva a entrar con Google.
Ya como administrador, los demás cambios de rol se hacen desde la pantalla Usuarios.
¿Olvidó el correo del administrador? En Firestore, colección usuarios, busque el documento con rol: administrador; su campo correo es el usuario.
¿Olvidó la contraseña? En la aplicación pulse ¿Olvidó su contraseña? y escriba ese correo; llega un enlace para crear una nueva (revise spam).
PerfilQué puede hacer
AdministradorTodo: usuarios, roles y permisos, predios, evaluaciones, recomendaciones e informes
EvaluadorRegistrar predios, realizar evaluaciones, generar recomendaciones y descargar los PDF
ConsultorConsultar predios, historial e informes, sin modificar nada
PropietarioSolo los predios registrados con su correo, con su historial y sus PDF

10. Crear usuarios para cada perfil

Los perfiles Evaluador y Consultor no se registran solos: los crea el administrador.

  1. Como administrador: Usuarios → Nuevo usuario.
  2. Nombres, apellidos, correo y Rol (Evaluador o Consultor) → Guardar.
  3. Firebase envía a ese correo un enlace para crear la contraseña (revise spam).
  4. La persona abre el enlace, define su contraseña e ingresa con correo y contraseña. Si el correo es de Gmail, también puede usar el botón Google y conserva el rol asignado.

Propietarios: pueden crear su propia cuenta con Cree su cuenta en la pantalla de ingreso; deben confirmar el correo antes de ver sus predios. También pueden entrar con Google.

Truco para probar todos los perfiles con un solo Gmail. Gmail entrega en su misma bandeja los correos con +algo antes de la arroba:
PerfilCorreo para crear en Usuarios
Evaluadorsucorreo+evaluador@gmail.com
Consultorsucorreo+consultor@gmail.com
Propietariosucorreo+propietario@gmail.com
Para estas variantes, ingrese con correo y contraseña, no con el botón Google. Para cambiar de perfil: Cerrar sesión e ingresar con otro.

11. Prueba completa del funcionamiento

  1. Como administrador o evaluador: Predios → Nuevo predio. Llene los datos, elija el sistema productivo (por ejemplo Lechería), la especie Bovinos con su inventario y, en Correo del propietario, el correo con el que ingresará el propietario → Registrar predio.
  2. Realizar evaluación → responda los indicadores (Cumple, Parcial, No cumple, No aplica) → Finalizar evaluación → confirme.
  3. Revise el puntaje, el nivel (Bajo, Medio, Alto o Excelente) y las recomendaciones.
  4. Descargue Informe técnico (PDF) y Recomendaciones para el propietario (PDF).
  5. Cierre sesión e ingrese como el propietario de ese correo: debe ver solo ese predio, su historial y los dos PDF.
Mensajes posibles al ingresar o usar la aplicación
MensajeQué hacer
«Correo o contraseña incorrectos.»Revise los datos o use ¿Olvidó su contraseña?
«Su cuenta no tiene un perfil en la plataforma.»La cuenta existe en Authentication pero no en la colección usuarios. Pida al administrador que la cree en Usuarios.
«Su usuario está inactivo.»El administrador lo inactivó, o su rol está inactivo.
«Su rol no tiene permiso para esta acción.»Revise los permisos del rol en Roles. Si ocurre en todo, falta el paso 4 (reglas).
El propietario no ve su predioNo ha confirmado su correo, o el predio se registró con otro correo. Tras confirmarlo, cierre sesión y vuelva a entrar.

TareaDónde y cómo
Política de contraseñasSeguridad → Authentication → Configuración → Política de contraseñas: longitud mínima 10, requerir un carácter numérico, modo Exigir → Guardar.
Correos en españolAuthentication → Plantillas → idioma Español.
IA de las recomendacionesServicios de IA → AI Logic → Comenzar → Gemini Developer API → Habilitar. Mientras no esté activa, la aplicación genera las recomendaciones con reglas de la norma y lo indica en el informe.

Hasta que Microsoft y Facebook estén configurados, sus botones muestran «Este método de ingreso no está habilitado en el proyecto de Firebase.», igual que Google en el paso 8.

13. Publicar en internet (opcional)

Para que cualquiera abra la aplicación sin su computador:

cd frontend
npm.cmd run build
cd ..\firebase
npm.cmd run desplegar:sitio
Queda en https://bienestar-animal-ica.web.app. El ingreso con Google funciona allí sin cambios, porque ese dominio ya está autorizado.

14. Cómo volver a ejecutarla otro día

Los pasos 3 a 6 y 8 se hacen una sola vez. Las siguientes veces basta con:

cd C:\Users\SuUsuario\Downloads\Aplicacion-a-la-inteligencia-artificial--main\Aplicacion-a-la-inteligencia-artificial--main\frontend
npm.cmd start

y abrir http://localhost:4200 en Chrome. Los datos están en Firebase, no en el computador, así que se conservan.

Modo demostración (sin Firebase, datos de prueba en el navegador): npm.cmd run demo en la carpeta frontend; ingreso con admin@ica-bienestar.local y contraseña CambiarEsta.2026.
