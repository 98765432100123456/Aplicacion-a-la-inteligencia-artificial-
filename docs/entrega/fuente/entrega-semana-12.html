Resumen de la entrega

ICA Bienestar Animal es una aplicación web para evaluar el bienestar animal en fincas con listas de chequeo por especie, puntaje automático, diagnóstico y recomendaciones con inteligencia artificial. Esta entrega cierra el primer sprint: el módulo de seguridad funciona de extremo a extremo y el resto del sistema queda diseñado.

Código del proyecto

Dos aplicaciones independientes que se comunican por HTTPS con una API REST. Cada carpeta tiene una sola responsabilidad y cada módulo del servicio sigue el patrón controlador, servicio y entidad.

backend/src
├── auth/         ingreso, token, recuperación
├── users/        gestión de usuarios
├── roles/        roles y catálogo de permisos
├── audit/        bitácora de auditoría
├── mail/         envío de correos
├── common/       guardas, decoradores,
│                 política de contraseñas
├── config/       variables de entorno validadas
├── database/     migraciones y datos iniciales
└── health/       verificación de estado
frontend/src/app
├── core/         sesión, API, interceptores,
│                 guardas de rutas, modelos
├── shared/       logo, diálogo, mensajes,
│                 encabezado, contraseña
├── layout/       barra superior y menú
└── features/
    ├── auth/     ingreso y recuperación
    ├── home/     inicio
    ├── users/    usuarios
    ├── roles/    roles y permisos
    └── account/  cuenta

Decisiones de organización

PrácticaAplicación en el código
Módulos por funcionalidadCada requerimiento vive en su carpeta; los módulos futuros (fincas, evaluación) se agregan sin tocar los existentes.
Seguridad por defectoTres guardas globales: límite de peticiones, token JWT y permisos. Una ruta es pública solo si se marca con @Public().
Validación en ambos extremosDTO con class-validator en la API y formularios reactivos en Angular con los mismos mensajes.
Configuración externaVariables de entorno validadas al arrancar; en producción las credenciales vienen de Secret Manager.
Esquema versionadoLa base solo cambia mediante migraciones de TypeORM.
Componentes reutilizablesDiálogo, mensajes y encabezado compartidos; el sistema visual se define una vez en styles.scss.
Modo demostraciónUn interceptor simula la API en el navegador para revisar la interfaz sin servidor ni base de datos.

Diseños de interfaz

La interfaz muestra el producto antes de prometerlo y organiza la información como un libro de registro: titulares grandes, filas separadas por líneas y un solo verde para la acción principal. Se adapta a teléfono, tableta y computador, y sigue la preferencia de modo oscuro del dispositivo.

Fundamentos visuales

ElementoDecisión
TipografíaManrope para la interfaz, con titulares de peso 800 y letras juntas; Unbounded solo en el logotipo.
ColorVerde pasto #4cc77f con texto oscuro (contraste 8.8:1) para la acción principal; fondo #f2f3f0 y noche #0e1210.
ComponentesBotones en píldora, interruptores para permisos, control segmentado, punto de estado, hojas inferiores en el teléfono y barra superior translúcida.
MovimientoCurva de salida cubic-bezier(0.23, 1, 0.32, 1), presión a scale(0.97) y entradas escalonadas; se desactiva con movimiento reducido.
AccesibilidadCero violaciones WCAG 2.1 AA en axe-core, objetivos táctiles de 44 px, foco visible, texto ampliado al 200 % sin desbordamiento.

Diseño de la base de datos

PostgreSQL 16 en Cloud SQL. El modelo cubre los ocho módulos del documento de requerimientos en 29 tablas, en tercera forma normal, y se validó ejecutando el script completo sobre una base vacía.

Reportescertificates, notifications

Decisiones de diseño

DecisiónJustificación
Listas de chequeo versionadasCada evaluación conserva la versión con que se diligenció; un índice único parcial permite una sola versión publicada por especie (RNF28).
Llave compuesta finca y especieImpide evaluar una especie que la finca no tiene registrada.
Respuestas en JSONBUn solo campo admite los siete tipos de respuesta del RF12.
Puntajes almacenadosEl historial y los tableros no recalculan cada evaluación, y el resultado no cambia si luego se ajustan las ponderaciones.
Texto original de la IASe conserva junto al texto revisado por el evaluador, para trazabilidad (RNF25).
Evidencias fuera de la baseSe guarda la ruta del objeto en Cloud Storage (RNF11).
Eliminación lógica de fincasConserva el historial de evaluaciones.
